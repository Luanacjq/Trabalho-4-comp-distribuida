TRABALHO 4 - TESTES DE DESEMPENHO COM O LINK EXTRACTOR
Divisão de tarefas da dupla
=======================================================

Ideia geral: cada pessoa cuida de uma versão da API (Python ou Ruby) do começo
ao fim e fica com uma ferramenta compartilhada. Os testes rodam nos dois PCs, e
cada PC roda as DUAS versões (Python e Ruby).


-------------------------------------------------------
PESSOA A - VERSÃO PYTHON (pronta, falta testar)
-------------------------------------------------------

Ambiente
[x] Copiar a versão Python da API (step5 do tutorial) para a pasta python/
[x] Criar o modo sem cache: variável USE_CACHE=false faz a API não usar o Redis
[x] docker-compose.yml com USE_CACHE=${USE_CACHE:-true}
[ ] Subir a aplicação e conferir se funciona com e sem cache

Ferramenta compartilhada: script do Locust
[x] locust/locustfile.py: usuário virtual faz 10 chamadas seguidas, cada uma
    com uma URL diferente, e espera 1-2 s antes de repetir
[x] locust/run_scenarios.py: roda todos os cenários de uma versão e salva os
    resultados em results/
[ ] Fazer um teste rápido e trocar as URLs que derem falha (combinar com a B,
    as duas versões têm que usar a mesma lista)

Slides
[ ] Descrição da ferramenta (Locust) e do script do usuário virtual (item 2)
[ ] Gráficos e análise da versão Python


-------------------------------------------------------
PESSOA B - VERSÃO RUBY
-------------------------------------------------------

Ambiente
[ ] Copiar a versão Ruby da API (step6 do tutorial) para a pasta ruby/
[ ] Criar o modo sem cache na API Ruby com a MESMA variável USE_CACHE
    (padrão true; false = não ler nem gravar no Redis)
[ ] docker-compose.yml seguindo o combinado:
      - serviços api, web e redis (o Redis tem que se chamar "redis")
      - API em http://localhost:4567/api/<url>
      - USE_CACHE=${USE_CACHE:-true} no environment da api
[ ] Testar o locustfile.py na versão Ruby

Ferramenta compartilhada: análise e gráficos
[ ] Script que lê todos os CSVs de results/ e monta uma planilha única
    (média, mediana, p90, p95, p99, req/s, falhas)
    Nome dos arquivos: <pc>_<versao>_<cache>_<N>u_stats.csv
    Exemplo: pc2_ruby_nocache_50u_stats.csv
    Usar a linha "Aggregated" de cada CSV
[ ] Script que gera os gráficos (tempo de resposta x nº de usuários)
    IMPORTANTE: comparar Python x Ruby DENTRO DO MESMO PC

Slides
[ ] Arquitetura da aplicação e descrição dos cenários de teste (item 3)
[ ] Gráficos e análise da versão Ruby


-------------------------------------------------------
JUNTAS
-------------------------------------------------------

[ ] Combinar a lista das 10 URLs (está em locust/locustfile.py)
[ ] Rodar os testes: cada PC roda Python e Ruby, um depois do outro
      PC1:
        python locust/run_scenarios.py --pc pc1 --version python --compose-dir python --host http://localhost:5000
        python locust/run_scenarios.py --pc pc1 --version ruby   --compose-dir ruby   --host http://localhost:4567
      PC2: os mesmos comandos, trocando pc1 por pc2
    - Não rodar os dois PCs ao mesmo tempo na mesma internet
    - Deixar o PC sem outros programas pesados abertos durante os testes
[ ] Subir os resultados (pasta results/) para o git
[ ] Slide 1: nomes e números de matrícula
[ ] Gráfico comparativo Python x Ruby e conclusão
[ ] Comparar os dois PCs: o resultado se repetiu nas duas máquinas?


-------------------------------------------------------
CENÁRIOS
-------------------------------------------------------

Versão:    python, ruby
Cache:     com cache, sem cache
Usuários:  1, 10, 50, 100
Duração:   2 minutos por teste (o Redis é esvaziado antes de cada teste)

Por PC: 2 versões x 2 modos de cache x 4 quantidades de usuários = 16 testes
        (cerca de 40 minutos)
Total:  32 testes nos dois PCs
